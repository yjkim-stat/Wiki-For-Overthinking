# LLM-as-a-judge

<!-- auto:begin -->

Using a language model to score, rank or label outputs in place of a human annotator or a programmatic checker -- in these sources both as an evaluation instrument and, increasingly, as a training reward. The sources that study it directly agree that it is far less valid than its usual validation suggests, and each names a different mechanism: exact-match agreement, the field's standard metric, overstates chance-corrected discrimination by 34 to 41 points across all 21 judges tested and every provider and capability tier; high test-retest reliability coexists with severe position bias, because stability of output is not correctness of process and a judge that deterministically prefers position A scores perfectly on retest while being maximally biased; judge rankings move by up to fifteen positions between benchmarks, so no leaderboard predicts another; preference scores fail to correlate with concrete measures of safety, world knowledge and instruction following because judges weight style over substance; forcing a single rating where several are defensible biases judge selection so badly that the chosen judge can be up to 31 percent worse than the one selected by eliciting the set of plausible ratings; and judges carry a latent numeric bias measurable by simply asking them to emit random numbers. Two sources report what does help. Evaluator accuracy rises monotonically with the reasoning tokens the evaluator is allowed to spend, so evaluation-time compute can substitute for generation-time compute; and a jury of different reasoning models beats a jury of repeated samples from one model and exceeds every individual member at segment level, with the jury's agreement-filtered output distillable into a 12B student that outperforms every open reasoning-model judge tested. The same source records two practical constraints that most work ignores: the field's standard evaluation prompt is specialised to the model it was written for and degrades every other model including that model's own successor, and enforcing strict output structure degrades evaluation quality across all models and most severely in the smallest, while loose formatting makes results hostage to parsing heuristics. Several sources here treat the judge as the thing to avoid rather than to improve -- verifying numerical claims by generating and executing SQL against the source table instead of asking a judge, and deliberately keeping a search reward separate from the benchmark's own evaluator so that optimising one cannot game the other.

## What we have settled

- **Established** — An evaluation baseline, prompt or output format inherited from prior work is an experimental variable, not a fixed point: comparisons against it routinely measure the mismatch between the apparatus and the model rather than the method under test.
  - Three instances in three domains, each with the confound measured rather than argued. Few-shot chain-of-thought prompting with dataset examples — the standard baseline in official model releases — costs a reasoning-specialized model roughly twelve points on GSM8K against no prompting at all (74.2% against 86.1%), so any method benchmarked as an improvement over it collects that deficit as free gain; the same paper shows an apparent nine-point scaling curve in the number of demonstrations is a rule-based parser learning to find the answer, with the underlying solutions unchanged. The standard MQM translation-evaluation prompt is specialized to the model it was authored against, and every other model including that model's own successor performs significantly worse under it, while enforcing structured output degrades judgement quality across all models and minor changes to the parsing heuristic move the reported metric with model output held fixed. And a vision-language selection rule reporting a 31.8-point gain over majority voting loses all of it to a control that merely matches the decoding format, because the baseline aggregated long chains while the method aggregated short answers.
